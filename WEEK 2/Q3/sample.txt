=====================================================
 THE TWO RUNNING TIMES
=====================================================
Method 1 - merge one array in at a time
  Round i merges a block of size i*n with an array of size n.
  Total = 2n + 3n + ... + kn = n(k(k+1)/2 - 1) = O(n k^2)
  The first array's elements get copied k-1 times.

Method 2 - merge in pairs, halving the count each round
  Every round moves all kn elements exactly once.
  The number of rounds is log2(k).
  Total = kn * log2(k) = O(n k log k)

Method 2 is better by a factor of Theta(k / log k).
Putting the leading constants back in, method 1 costs about
n k^2 / 2 and method 2 about n k log2(k), so the speedup to
expect in practice is k / (2 log2 k).
At k = 64 that predicts about 5.3 times.

=====================================================
 CONCLUSION
=====================================================
Method 1 : O(n k^2)     - repeated merging into a growing
                          block, so early elements are
                          copied over and over
Method 2 : O(n k log k) - a balanced merge tree, so every
                          element is copied once per round
                          and there are only log2(k) rounds

Both were checked at every size: the output is sorted and
holds all kn elements.

Time Complexity  : method 1 O(n k^2), method 2 O(n k log k)
Space Complexity : O(n k) for both - the merged output plus
                   one working buffer of the same size
