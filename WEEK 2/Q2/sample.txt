=====================================================
 THE TWO RECURRENCES
=====================================================
Ordinary merge sort
  T(n) = 2 T(n/2) + O(n)
  Master theorem : a = 2, b = 2, so n^(log_b a) = n^1 = n.
  The merge cost O(n) matches, so T(n) = O(n log n).
  Depth of recursion = log2 n.

Three-way merge sort
  T(n) = 3 T(n/3) + O(n)
  Master theorem : a = 3, b = 3, so n^(log_b a) = n^1 = n.
  The merge cost O(n) matches, so T(n) = O(n log n).
  Depth of recursion = log3 n = log2 n / log2 3.

ANSWER: the modified merge sort is still O(n log n) in the
worst case.  Splitting into thirds only changes the base of
the logarithm, and a change of base is a constant factor
(1 / log2 3 = 0.6309), which O-notation absorbs.

=====================================================
 CONCLUSION
=====================================================
At n = 32000 on random input:

  comparisons / (n log2 n)   2-way 0.915   3-way 1.142
  moves       / (n log2 n)   2-way 1.001   3-way 0.634

Both ratios are flat as n grows, which is what O(n log n)
looks like when measured.  Neither variant escapes the class.

The three-way version makes fewer moves, because it has
log3 n levels instead of log2 n and every level copies n
elements.  It makes more comparisons, because choosing the
smallest of three heads costs 2 comparisons instead of 1.
The two effects nearly cancel, and neither changes the
asymptotic answer.

Time Complexity  : O(n log n) for both variants
Space Complexity : O(n) for both - one temporary array of n
                   integers, plus O(log n) recursion stack
