# Q4 — Matrix Multiplication using Strassen's Method

> Multiply two square matrices of size `n × n` using Strassen's divide-and-conquer
> method, and compare against the naive triple loop.

## Problem Statement

Write a C program to multiply two square matrices of size `n × n` using
Strassen's method.

---

## The Algorithm

Split each matrix into four `n/2 × n/2` quadrants:

```
A = | A11  A12 |    B = | B11  B12 |    C = | C11  C12 |
    | A21  A22 |        | B21  B22 |        | C21  C22 |
```

The block algorithm needs **eight** half-size products
(`C11 = A11B11 + A12B21`, and so on). Strassen computes **seven** instead:

```
M1 = (A11 + A22)(B11 + B22)
M2 = (A21 + A22) B11
M3 = A11 (B12 − B22)
M4 = A22 (B21 − B11)
M5 = (A11 + A12) B22
M6 = (A21 − A11)(B11 + B12)
M7 = (A12 − A22)(B21 + B22)
```

and recovers the quadrants by addition alone:

```
C11 = M1 + M4 − M5 + M7
C12 = M3 + M5
C21 = M2 + M4
C22 = M1 − M2 + M3 + M6
```

Trading one multiplication for eighteen block additions is what changes the
exponent — additions cost `Θ(n²)` per level, which is asymptotically cheaper
than the recursive products.

---

## Complexity

```
T(n) = 7·T(n/2) + 18(n/2)²
```

By the Master Theorem with `a = 7`, `b = 2`, `f(n) = Θ(n²)`:

```
log_b(a) = log₂ 7 ≈ 2.807  >  2
```

Case 1 applies, so:

```
T(n) = Θ(n^log₂7) = Θ(n^2.807)
```

against the naive `Θ(n³)`. The saving compounds with depth: at each level
Strassen does 7/8 of the work the block algorithm would.

### Reading the output

**The multiplication column is exactly `7^log₂n`** — 7, 49, 343, 2401, 16807,
117649, 823543. These are `7¹` through `7⁷`, exact powers of seven at every
size. The recursion bottoms out at single elements, so the count is precisely
the number of leaves in a 7-ary tree of depth `log₂ n`. This is the exponent
`n^2.807` confirmed as an identity, not an estimate.

**The ratio column grows steadily: 1.14 → 2.55.** This is
`n³ / n^2.807 = n^0.193`, the asymptotic gap widening with n. At `n = 128`
Strassen does 823,543 multiplications where the naive method does 2,097,152 —
a factor of 2.55 fewer.

**But the total column tells the honest story.** Counting additions too,
Strassen's totals (25, 247, 2017, …) are *worse* than naive (12, 112, 960, …)
at every size shown. The 18 block additions per level are real work, and they
dominate until n is large enough for the multiplication saving to overtake
them. The gap is closing though — the ratio of totals falls from 2.08× worse
at `n = 2` to 1.36× worse at `n = 128`.

This is why production implementations of Strassen cut over to the naive
algorithm below a threshold (typically n ≈ 32–128) rather than recursing all
the way to single elements. Asymptotically better does not mean better at
every size, and the table shows exactly where the crossover has yet to happen.

**Every product is verified.** The Strassen result is compared entry-by-entry
against the naive triple loop at every size, and any mismatch aborts the run.
The counts are only printed because all seven sizes produced identical
matrices by both methods.
